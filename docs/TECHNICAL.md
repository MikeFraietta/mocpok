# MocPok local demo

Describe a dragon maze adventure, use a model running on this Mac to choose its story and configuration, then preview and download the board and rules.

## Start

1. Open Ollama. The locally installed model must be named `mocpok`.
2. In this folder run `python3 server.py`.
3. Open **http://127.0.0.1:8765** in a browser. Keep the server window open.
4. Describe a dragon maze. You can ask for easy, family, or hard difficulty. Make the game, inspect the preview, and download the STL and rules.

Python 3.9 or newer is required. The server and maze builder use the Python standard library. No package installation, cloud API, or API key is required. Ollama must already contain the model; downloading it is a separate setup step.

## What the prototype does

- An existing open-weight model runs locally through Ollama, at `127.0.0.1:11434`.
- The model creates the title, theme, and mission, and selects a supported difficulty and maze seed.
- The model returns five fields: title, theme, mission, maze seed, and difficulty. Its real draft is saved in the model metadata. The app then adds the tested setup, movement, and winning rules; those mechanics are supplied by code rather than generated prose.
- A separate board generator creates an 8-by-8 maze and verifies that all 64 cells are connected.
- Every successful generation saves `plan.json`, `board.svg`, `board.stl`, `rules.md`, and `print-kit.zip` in a new `projects` subfolder. The ZIP also includes the original component STLs present in the local `components` folder; these reuse prepared prototype designs rather than being newly generated by the model.
- The browser shows a real generated board preview. The STL is a 216 × 216 mm board, intended to use the separately printed explorers and keys and an ordinary six-sided die.

This is local inference and customization, not training or fine-tuning new model weights. If the optional local `library.py` search module and its index are present, the app provides up to three short, labeled reference excerpts to the model and returns those references for inspection. Otherwise it uses no rulebook library. Connectivity checks do not mean a generated game has been physically playtested or balanced. Creating a project does not start a print.

The server listens only on this Mac's loopback address. It does not expose a website to the room or the internet. It sends no requests to external services, and bypasses proxies for the local Ollama request. Stop it with Control-C.

## Fixed game rules

Two explorers cooperate. Either can collect either or both shared keys. Both keys unlock the exit. Roll one ordinary six-sided die once for the team; each explorer gets up to the full rolled movement through open passages, never diagonally or through walls. Waiting and sharing squares are allowed. After both have moved, the clock advances once, unless both already escaped. Easy starts at 0, family at 2, hard at 3; the dragon wakes at 12. An explorer at an unlocked exit escapes immediately. Both must escape before the clock reaches 12.

## API for the local page

- `GET /api/health` returns Ollama availability and whether the `mocpok` model is installed.
- `POST /api/generate` accepts JSON `{ "prompt": "A friendly dragon maze, easy difficulty" }`, with a prompt of 1–2,000 characters. It returns `project_id`, `plan`, `board`, a small `maze` summary, `preview_svg`, download `assets`, and local `model` metadata.
- `plan` contains `title`, `theme`, `mission`, `setup`, `round`, `winning_and_losing`, `maze_seed`, and `difficulty`.
- `assets` contains `svg`, `stl`, `rules`, `plan`, and `kit` URLs at `/api/projects/<uuid>/<filename>`.
- `references` lists source labels and the short excerpts supplied to the model; this records supplied context, not proof that a particular answer was grounded in it. `library_counts` describes the optional indexed library.
- Errors are non-success HTTP responses containing `error` and `code`. There is no canned success fallback. Only one model generation is accepted at a time.

The backend calls `maze.generate_game(seed, difficulty)`, `maze.render_svg(board, title=...)`, and `maze.export_stl(board)`. The maze module and browser page are separate local files in this same folder.

The model request uses Ollama's `/api/generate` endpoint with an explicit nonthinking ChatML prompt. This bypasses the inherited chat template's thinking block and produces a short five-field JSON draft.

## Troubleshooting

If the status says the model is unavailable, open Ollama and check that `ollama list` includes `mocpok`. If a generation fails, the page reports the actual failure; inspect the model/server window and try again. If the port is busy, stop the other demo server or run `python3 server.py --port 8766` and open that port instead.

For sharing code on GitHub, include the app, maze tool, setup instructions, model configuration, and chosen original examples. Do not commit API keys or model-weight downloads. Other people can install the named model locally.
